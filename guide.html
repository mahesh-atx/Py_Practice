Python roadmap

Know what to learn, and what to practice next.

Move in order. Learn a small idea, solve several problems, then step up in difficulty.

Strategy 01 · Deliberate Practice

Deep Analysis: Think before you write syntax.

The best problem solvers don't rush to touch the keyboard. They spend 70% of their time deconstructing the logic on paper, mapping data flows, and anticipating edge cases before running code.

Deconstruct constraints

Ask: Can inputs be empty, negative, or duplicates? Boundary checks prevent off-by-one errors.

Trace the data flow

Sketch Input → Transformation → Output. Know what each intermediate variable represents.

Draft comments first

Outline the solution in 3–4 numbered comments in plain English, then replace comments with Python code.

Manual dry run

Step through a small test case with a pen. If you can't trace it by hand, the interpreter won't fix it.

Strategy 02 · Error Recovery

Six Things To Do When You Don’t Know What To Do

Hit a wall with a baffling error or unexpected test failure? Don't randomly change code hoping it works. Follow this battle-tested 6-point checklist:

1
Read the traceback from bottom to top

The very last line gives the exact error type (KeyError, TypeError) and line number. Start there.

2
Print variables & inspect actual runtime types

Insert print(type(val), repr(val)). Most subtle bugs happen when a string looks like a number or a function returns None.

3
Isolate the failing calculation in a 3-line scratchpad

Strip away function wrappers and loops. Test only the exact expression that produces the invalid outcome.

4
Question your mutable assumptions

Did you do x = my_list.sort() (which evaluates to None)? Remember that Python in-place methods return None.

5
Rubber-duck your algorithm out loud

Explain what each line is supposed to accomplish in full spoken sentences. The gap between your mental model and the code will emerge immediately.

6
Step away for a 5-minute break

Tunnel vision is real. Walking away resets dopamine and working memory — you’ll spot the missing index within seconds of returning.

Strategy 03 · Knowledge Retention

The Feynman Technique: Explain to build lasting intuition.

Passing test cases proves your code works once; explaining why it works ensures you can reconstruct it months from now during an interview or production sprint.

Summarize the invariant:

State in one sentence what condition stays true on every single loop iteration.

Compare trade-offs:

Did you choose a hash map (O(1) lookups, higher memory) or sorted list (O(log n) lookups, zero extra memory)?

Teach a beginner:

If you can explain recursion or list comprehensions without jargon, you have truly mastered the concept.
